\section{Task Decomposition of the Prism Adaptation Workflow}
\label{sec:task-decomposition}

This section visualises how the prototype was designed from the participant's point of view. Rather than starting from scripts or interfaces, the design is described as a small set of repeated interaction loops and block transitions. The overall workflow follows a \emph{measurement--exposure--measurement} structure: a baseline task is first performed without perturbation, then an exposure block is completed under one of the implemented visual effects, and finally the same measurement task is repeated in a post-exposure phase. The key distinction is therefore between tasks that \emph{measure} a spatial estimate and the task that is intended to \emph{change} it through repeated visuomotor correction.

Because the project compares both input modes and effect modes, the design also had to preserve comparability across conditions. Changing from controller input to embodied input, or from one perturbation to another, should not change the basic block order, the role of baseline and post-exposure measurement, or the participant's understanding of when a response has been accepted. An additional design consideration therefore concerns how responses are confirmed and what visual information is available before and after an action. The default controller implementation uses trigger confirmation, whereas embodied interaction uses dwell-based confirmation. The system also includes prototype-specific Heisenberg-mitigation variants, such as opposite-hand confirmation and controller-hover confirmation. These variants should therefore be understood as configurable design alternatives in the prototype rather than as fixed assumptions inherited from the prism-adaptation literature. Across the tasks, the most important feedforward cues are the currently shown target or stimulus layout, while the most important feedback cues are the accepted response, the loading/progress indicator, and the visible shift to the next required interaction. Figures~\ref{fig:prism-task-cycles} and~\ref{fig:design-task-posture} therefore work together: the first shows the abstract task structure, while the second ties the task modes to the intended body posture and wall-based interaction setup used during testing.

The participant's body placement was intentionally constrained by design. Across the tasks, the participant remains oriented toward the same target wall and works within one frontal interaction space, moving between a lowered resting posture and a raised aiming posture rather than walking or reorienting between trials. This keeps the bodily setup stable while allowing the task stimulus and response rule to change. In design terms, the task differences should come from what is shown on the wall and how that response is interpreted, not from a different room layout or a different whole-body movement pattern.

\subsection{Open-Loop Pointing}
\label{subsec:open-loop-decomposition}

Open-loop pointing is the clearest measurement task in the system because each trial yields a single signed endpoint deviation relative to one visible target. The participant begins with the arm lowered alongside the body, raises it into the frontal workspace in a semi-straight configuration, aims toward the target, commits the response, and lowers the arm again. In controller mode, commitment occurs through the trigger; in embodied mode, the endpoint is accepted once the fingertip remains stable for approximately 1.5\,s. The most important feedforward cue is simply the visible target location on the board, while the most important feedback is the accepted endpoint together with the short loading bar and transition to the next trial. As a design element, open-loop pointing is intended to provide a minimal and repeatable measurement loop that can be compared directly between baseline and post-exposure.

\subsection{Line Bisection}
\label{subsec:line-bisection-decomposition}

Line bisection uses almost the same motor pattern as open-loop pointing, but the participant is no longer given a point target. Instead, a horizontal line is shown and the participant must infer its midpoint before aiming. The task can therefore be understood as the same reset--aim--confirm loop combined with a stronger perceptual judgment component. The visible line provides feedforward about where the midpoint should be estimated, while the main feedback again consists of the accepted response, the resulting readout, and the transition to the next trial. The output measure is the signed deviation from the true midpoint. In design terms, line bisection therefore reuses the same response structure as open-loop pointing while changing the perceptual demand.

\subsection{Landmark}
\label{subsec:landmark-decomposition}

Landmark has a different structure from the other tasks because it is not primarily a target-acquisition task. The participant inspects the displayed stimulus, compares the two visible line segments, decides which side appears longer, and then selects the corresponding response. For that reason, landmark is better described as a comparative perceptual judgment followed by a discrete choice. Its feedforward is the visual organisation of the stimulus itself, while its feedback is the confirmation that the choice has been accepted and that the next trial is loading. In the present project, landmark is retained mainly as a supplementary assessment task. It broadens the assessment repertoire, but it does not define the main baseline--exposure--post-exposure loop in the same way as open-loop pointing and line bisection.

\subsection{Exposure}
\label{subsec:exposure-decomposition}

Exposure is the adaptation-inducing task and is therefore structured differently from the measurement tasks. Instead of isolating one response and resetting to a neutral starting posture after each accepted trial, the participant repeatedly redirects the response inside a fixed horizontal three-target layout. One target is active at a time, and the active target is repeatedly reselected within that layout rather than following one fixed left-to-right sequence. In controller mode, confirmation is normally trigger-based, although opposite-hand confirmation and controller-hover confirmation are also supported; in embodied mode, confirmation is dwell-based. The dominant feedforward cues are the active-target highlight, the stable spatial layout, the bullseye cue on the currently selected target, and the loading or transition cue that precedes the next required movement. The dominant feedback cues are the hit or miss outcome, the hit marker, and the visible shift to the next target under the active perturbation. In design terms, exposure is the only task whose structure is intentionally repetitive enough to drive correction under perturbation rather than simply record one accepted estimate.

\subsection{Measurement Tasks Versus Exposure}
\label{subsec:measurement-vs-exposure}

The workflow therefore contains two different experimental logics. Open-loop pointing and line bisection are measurement tasks that isolate a single accepted response and compare it between baseline and post-exposure phases. Exposure, by contrast, is a repeated target-acquisition task whose purpose is to induce sensorimotor adaptation under perturbation. Landmark remains conceptually separate as a perceptual comparison task that may be useful for later clinical use, but is less central to the present healthy-participant workflow. These distinctions also define what the later implementation has to preserve: one stable baseline--exposure--post-exposure structure, configurable confirmation variants across input modes, and task-specific differences that remain local to the task itself rather than changing the overall workflow.

\subsection{Data Collection and Analysis Design}
\label{subsec:analysis-layer-design}

The task decomposition above defines how the participant should move through the prototype, but it also defines what the system must record. Once the task loops had been specified, the next design question was therefore how to translate those loops into a data structure that would still be interpretable after the session had ended. The guiding principle was to keep the smallest meaningful unit of behaviour intact: one accepted measurement trial should remain one readable record, one exposure attempt should remain one readable adaptation event, and the whole session should still be reconstructable as one baseline--exposure--post-exposure sequence.

This produced two linked design requirements. First, each task needed a task-specific output structure that matched its own logic rather than forcing all tasks into one identical metric. Second, those task-specific outputs needed to be attached to enough shared session context that they could be compared across task, effect, and input conditions. The second requirement concerns how those outputs are used collectively. The project does not only ask whether one participant adapted in one sequence of trials; it asks how different combinations of task, effect, and input mode behave. Every accepted response therefore also needs session-wide context such as the active perturbation, the chosen input mode, the confirmation rule, the current phase of the experiment, and a session identifier that links metadata, event rows, continuous samples, and later summaries together. Taken together, the task side and the analysis side describe one continuous design. The Unity runtime specifies what the participant should see and do, while the data structure specifies what the system must preserve so that those actions can later be interpreted as baseline performance, exposure behaviour, aftereffects, spatial bias, and movement form. The implementation chapter can then be read as the concrete realization of these design decisions.
